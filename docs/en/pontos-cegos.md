# Blind-spot matrix of the electoral process

Each row describes a step of the pipeline, from software development to results publication. It uses only official documentation or an indicated source. "In principle" describes what could go wrong, without asserting that it did. Press sources are marked as such.

> **General limit of this matrix.** The consistency tests (A4, H9) compare files that the TSE itself publishes and that originate from the same software. They **do not rule out** a coherent alteration made between the closing of the voting machine and publication, nor do they verify whether the recorded vote matches the typed vote. What covers each gap is in [A18](a18-alteracao-no-meio.md) and [A19](a19-voto-digitado.md).

Convention for the column "What this audit tested": the number in brackets refers to the analysis (H1 to H10 of Phase 1, A1 to A10 of Phase 2).

## Separation of what was tested

**(a) Tested by this audit:** consistency BWeb x votacao_secao x totalization; digital BU x BWeb; RDV x BU; hash binding of the files; log x BU (sample); machine actually used x expected; coherence across offices; turnout profile (first round); section statistics (Phase 1).

**(b) Testable by whoever has inputs we do not have:** printed poll-receipts photographed by party observers and parties; polling sheets; oversight-entity access to Sistot and to the source code; cryptographic specification of the voting-machine files.

**(c) Not testable by any public data:** the content of the code running on the voting machine; the identity of each enabled voter; the secrecy of the individual vote.

This matrix makes no claim about authorship or intent.
